# M7Arc 实施路线

## 1. 交付顺序

P0 建立完整引擎的可调用边界，P1 交付可用归档浏览与提取，P2 完成完整压缩更新，P3 补齐 File Manager 工作流，P4 完成 Mac 文件语义与系统体验，P5 覆盖工具和 SFX，P6 形成公开发行产品。

窗口字段与联动以 [对话框规格](DIALOG_SPEC.zh-CN.md) 为实施依据，格式与方法能力以 [格式目录](FORMAT_CAPABILITIES.zh-CN.md) 为依据。

正式 1.0 对应功能迁移矩阵中全部已规划的可移植能力，以及 Windows 特有功能的明确替代。预览版本单独说明已完成范围。

| 阶段 | 当前实现 | 主要代码 | 发行验收 |
| --- | --- | --- | --- |
| P0 构建与引擎边界 | 全格式共享引擎、官方 CLI、双架构构建 | `cmake/`、`src/engine/` | 两种架构通过引擎集成测试 |
| P1 浏览与提取 | 目录、提取、测试、密码重试、进度和取消 | `ArchiveModel`、`OperationController` | 真实加密档案与 GUI 往返通过 |
| P2 完整创建与更新 | 全参数创建、更新、分卷、成员改写、复合流格式 | `ArchiveDialogs`、`ArchiveEngine` | 十种 GUI 格式预设往返通过 |
| P3 文件管理工作流 | 双面板、四类传输、嵌套回写、编辑、全部视图 | `MainWindow`、`FilePane`、`EditSession` | 编辑会话与 10 万条目验证通过 |
| P4 macOS 文件与系统能力 | 元数据、Services、Quick Look、拖放、卷与废纸篓 | `src/platform/` | 元数据互操作与系统入口集成测试通过 |
| P5 工具与 SFX | 摘要、基准、分割合并、原生模块与七类 SFX | `HashDialog`、`BenchmarkDialog`、`apps/desktop/src/tools/` | Mac SFX 分发通过；Windows 实机运行待验收 |
| P6 发布与稳定性 | 双架构 DMG、ad-hoc 签名、中英文、文档与 CI | `packaging/`、`.github/workflows/` | macOS 13、Intel 真机与完整跨系统样本待验收 |

`0.1.0-alpha.1` 提供上述可执行功能。进入 1.0 前，完成最低支持系统、Intel 真机、Windows SFX 实际运行及更完整的跨系统归档样本验收。实测结果以[发行验证记录](VALIDATION.zh-CN.md)为准。

## 2. P0：完整引擎可调用

1. 在现有独立 M7Arc 根目录建立构建工程，使用 `third_party/7zip` 固定源码快照和来源记录，保留上游内部目录。
2. 将 Arc_gcc 与 Alone2 中所需源文件整理为显式 CMake 清单，按平台和架构选择对象。
3. 建立 `sevenzip_objects → m7arc_engine`，唯一使用 LoadCodecs 注册宿主。
4. 实现 Unicode/属性/错误/回调转换；提取 Agent 中有用的非视觉逻辑。
5. 构建官方 `7zz` 和无 GUI 的引擎调用样例，输出真实格式/方法能力目录。
6. 在 arm64/x86_64 分别构建；为后续应用预设 macOS 13 部署目标。

完成条件：库内格式、编解码方法与同版 `7zz i` 对齐；直接 API 能打开归档、列出真实属性并提取成员；没有 Win32 控件或主函数进入库。

## 3. P1：归档浏览与提取预览版

实现 MainWindow、单面板、路径导航、ArchiveSession、条目模型、基础任务队列和文件打开入口。接入完整 61 个 handler 的动态格式中心、指定格式打开和只读能力表现；RAR/RAR5、镜像、文件系统、可执行文件、文档容器及 Hash 清单均保留入口。

完成选择提取、全部提取、测试、五种覆盖模式与六按钮覆盖请求、完整/当前/平铺/高级绝对路径、密码重试、分卷输入、内存请求、进度/暂停/后台/取消和逐项错误结果。大归档后台读取目录，列表使用值快照。

完成条件：GUI 直接调用引擎；用户能从 Finder 打开归档，选择成员解压到目标目录，错误密码可重新输入，取消后 UI 仍可用。提供能从构建目录启动的 `.app`。

## 4. P2：全部压缩参数与更新

建立结构化 ArchiveOptions，以原版密集两列呈现格式、等级、方法、字典、词大小/阶数、solid、线程、压缩/解压内存、分卷、自定义参数、加密、路径、更新及操作选项；更多选项保留链接、时间精度、三态时间字段和有效高级方法/滤镜。支持 7z、ZIP、GZip、BZip2、XZ、TAR、WIM 七类写入格式；单流格式与 tar.gz/tar.bz2/tar.xz 管线清晰显示。

实现添加/替换/更新/刷新/同步、删除成员、重命名、注释和包内目录操作，按实例能力启用。将所有归档改写集中到临时输出与提交路径；实现成功后删除源的逐项语义。

完成条件：GUI 创建的档案由官方 Windows/macOS 7-Zip 读取和测试；选项传到实际引擎并能从结果属性确认关键效果；取消或写入失败保留原归档；内存选择没有超出引擎限制。

## 5. P3：File Manager 完整工作流

双面板与活动面板命令分发、四类文件传输、收藏/历史、按掩码选择、图标/列表/详细/平铺视图、动态列、自动刷新和 viewer/editor/diff 配置统一进入应用层。

实现父子归档会话、不同层密码、编辑临时文件、逐级回写和明确的保存/放弃/取消结果。会话与真实条目身份绑定，面板切换不会改变编辑目标。包内向外移动在目标成功后删除源，删除失败显示复制完成但源仍保留。

补齐六页选项窗口：系统关联、菜单、文件夹、查看/编辑/Diff、设置、语言。属性页按文件、文件夹及各层归档动态枚举全部属性；不受默认列表列数限制。选项中的格式关联与菜单命令由注册表和命令模型枚举。

完成条件：正常完成“打开 outer.zip → 编辑 inner.7z 的文件 → 回写 inner → 回写 outer”；取消回写保留当前层，任一层失败保留编辑结果；跨面板移动只在目标成功后处理源。

## 6. P4：macOS 文件语义与系统体验

元数据工作尽早和 P2 并行设计：MacMetadata 负责 AppleDouble/xattrs/resource fork/FinderInfo/标签/ACL 及真实 birth time。ZIP 互操作以系统归档工具创建和展开的样本验证，7z/TAR 验证 M7Arc 自身完整往返和普通工具可读性。

补齐本地文件操作、symlink/hardlink、应用 bundle 作为目录数据的压缩和适当的 UI 呈现、挂载卷、网络挂载位置、废纸篓、文件 promise 拖出和拖入。

实现 Services、文件关联/Dock、应用内 Quick Look、Finder 归档预览扩展和可安装 Quick Actions。系统入口复用统一的应用命令。

完成条件：带资源叉、Finder 标签和执行权限的真实测试文件完整往返；可从 Finder 压缩、提取和预览；归档内文件拖到 Finder 后得到真实文件，取消拖放不留下正式输出。

## 7. P5：工具与 SFX

迁移 10 个注册 hasher，支持单算法/多算法/全部、单文件及数据/文件名总和、SHA256/SHA1 清单输出及清单验证的通过/缺失/不匹配结果。Benchmark 保留字典、线程、轮数、压缩/解压当前与平均统计、CPU 使用率、评分、停止/重启和日志。补齐普通文件分割/合并、链接操作与原始属性检查。帮助覆盖这些功能的真实使用方式。

使用上游现有接口支持外部 Codecs/Formats：保持内建格式，统一相关编译宏，补齐显式模块目录、内外 codec 互用、启动加载与关闭释放。提供当前接口的 Mac 模块构建示例，主应用处理第三方模块加载所需的 library validation entitlement；预览扩展使用随包集合。

保留 Windows SFX 输出，验证 Unix console SFX。Mac 自解压分发使用已签名提取器 app + 独立 payload 的 DMG 形式；发布者模式可嵌入 payload 后自行签名公证。安装器运行配置独立显示目标系统和命令。

完成条件：工具行为与上游相符；每个 SFX 输出清楚标识执行平台，在对应目标系统实际提取成功；Mac 签名包的内容组织与用户生成 payload 的流程兼容。

## 8. P6：可公开发行

整理打包脚本、arm64/x86_64 依赖、Qt 插件、扩展、翻译、图标和帮助；从内到外完成 ad-hoc 签名并验证重定位启动。建立英文贡献指南、源码构建与第三方许可说明。

以 GitHub Releases 为下载渠道，DMG 为用户安装包。GitHub Actions 根据版本标签构建应用、打包运行依赖、执行 ad-hoc 签名与发行验证，再上传 DMG 和版本说明；源码 ZIP/TAR 由 GitHub 独立提供。当前无需 Developer ID 与公证凭据即可发布。预览包明确标注当期已经实现的功能、已验证架构及未完成 Developer ID 签名和公证的状态。后续取得证书时增加可信发行渠道。

在 Apple Silicon 与 Intel、最低支持系统与最新正式系统上安装和运行，验证 Finder 入口、Quick Look、文件访问、关联、密码与多卷归档。通过跨系统互操作样本验证不同引擎构建结果。

完成条件：下载到干净用户环境中的 DMG 可正常安装和使用；主 app、引擎、Qt 与扩展架构一致；公开源码可重建；功能矩阵全部落到实际产品入口或已说明的平台替代。

## 9. 有明确目的的验证

| 场景 | 要发现的具体失败 | 失败后改变什么 |
| --- | --- | --- |
| 新库与 `7zz i` 对比 | 链接丢失静态注册格式、codec/hasher 或写入能力 | 调整对象清单和注册宿主 |
| 原生外部 codec/format 模块 | ABI/架构不符、外部 format 找不到内建 codec、签名策略阻止合法加载 | 修正宏、方法导出、加载路径与主 app entitlement |
| 中文/emoji/空格路径往返 | Qt UTF-16 与上游 wchar/UTF 转换错误 | 修正唯一字符串转换边界 |
| 加密/solid/分卷/RAR5 样本 | 未正确传密码、错误选择 handler、缺少分卷 | 修正 callback 和打开会话 |
| 七类创建与关键参数 | UI 参数被丢弃、错误方法、单流误打包 | 修正参数模型与 TAR 管线 |
| 源/输出内容直接比较 | 桥接造成数据缺失或错误成员映射 | 修正 stream、索引或读写生命周期 |
| 取消/覆盖/输出空间不足 | 提交前破坏原档、仍删源、回调等待不解除 | 修正提交边界与作业状态 |
| 同名成员、大小写/规范化冲突 | 选择错条目或目标静默覆盖 | 修正 EntryRef 与目标名称冲突处理 |
| 外来归档越界路径与链接 | Qt 新流程绕过上游提取边界 | 恢复正确提取入口与输出路径规则 |
| 嵌套编辑/取消/父层只读 | 修改被丢弃、取消仍退层、写错父归档 | 修正 ArchiveSession 与 EditSession |
| 四类复制与移动 | 目标失败但源已删除、部分成功被报成全成功 | 修正传输阶段和逐项结果 |
| AppleDouble/标签/资源叉/时间 | Mac 文件属性缺失或错误恢复 | 修正 MacMetadata 与格式选项 |
| 10 万条目、大文件、solid 预览 | UI 主线程阻塞、一次性巨大复制、无效重复提取 | 修正模型批量发布、临时文件和任务调度 |
| 同硬件同参数对比官方 CLI | UI 桥接引入明显多余复制、解压或调度开销 | 分析具体耗时并修改相应路径 |
| 干净机器 DMG 安装 | 缺库、架构不匹配、签名/公证或扩展加载失败 | 修正安装布局与签名流水线 |

测试按改动涉及的失败类型选择。引擎算法保持上游代码时，主要验证链接、选项、流、成员身份和平台输出；不为外观间距等可逆调整建立重复单元测试。

## 10. 首轮开发工作包

| 工作包 | 具体产物 | 验收 |
| --- | --- | --- |
| A：工程与依赖 | 根 CMake、架构 preset、固定 7-Zip/Qt 版本 | 可重复生成构建目录 |
| B：引擎源清单 | EngineSources、对象库、共享引擎 | 格式注册目录完整 |
| C：调用边界 | EngineTypes、字符串/属性转换、回调接口 | 无 GUI 样例列举并提取成员 |
| D：Qt 切片 | 主窗口、归档表、选择提取、任务状态 | 可运行 `.app` 完成一次提取 |
| E：平台研究落地 | MacMetadata 数据样本、文件 promise 与预览接口样例 | 明确实际平台输入输出契约 |

A → B → C 是引擎依赖链；D 的界面实现可以和 B/C 并行，随后接入；E 可以由熟悉 macOS 的开发者独立推进。先把一次真实操作从 UI 走到原引擎并正确返回，再扩展操作集合。

## 11. 投入与范围边界

工程投入的主要变量是嵌套编辑、跨卷失败处理、Mac 元数据互操作、文件 promise 拖放与系统扩展发行。Qt 应用、共享引擎和双架构构建已落地；最低系统、Intel 真机与完整跨系统互操作验收仍需对应环境。

Mac App Store 发行需要 App Sandbox 下的文件授权与持久访问设计，作为独立渠道迭代；首版采用直接 DMG 分发。可写 Zstd、新压缩算法、云同步和额外平台 UI 属于产品后续扩展，不影响既定官方能力迁移的完成定义。
