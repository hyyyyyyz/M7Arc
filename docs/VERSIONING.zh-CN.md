# 版本编号

应用采用 [SemVer 2.0.0](https://semver.org/lang/zh-CN/)，格式为 `主版本.次版本.修订版本[-预览阶段.序号]`。首个可执行预览使用 `0.1.0-alpha.1`。

| 变更 | 示例 | 使用规则 |
| --- | --- | --- |
| 小修复 | `0.1.0` → `0.1.1` | 修复错误、兼容性问题、翻译或视觉细节，不改变已有工作流 |
| 新增功能 | `0.1.1` → `0.2.0` | 新归档操作、新系统入口、新参数或完成一个功能阶段 |
| 正式完整版本 | `0.x.y` → `1.0.0` | 完成约定功能迁移及发行验收，版本号本身不代表 Apple 公证状态 |
| 不兼容变化 | `1.x.y` → `2.0.0` | 用户设置、公开命令行接口或插件接口需要不兼容变化 |
| Alpha | `0.2.0-alpha.1` → `0.2.0-alpha.2` | 功能开发期间的可运行预览；每次公开构建递增序号 |
| Beta | `0.2.0-beta.1` | 本次版本功能已齐，继续兼容性与使用验证 |
| RC | `0.2.0-rc.1` | 候选发行版，只接收影响发布的问题修复 |
| 正式发行 | `0.2.0-rc.2` → `0.2.0` | 对应版本验收完成，去掉预览后缀 |

`0.x` 阶段仍按修复升 patch、新功能升 minor 的规则执行；发生不兼容变化时升 minor，并在变更说明中写明影响。预览期间的修复递增预览序号；已发布稳定版的修复增加 patch。重新打包已公开版本也使用新版本号，不覆盖既有版本附件。

## 唯一版本源

仓库根目录 [VERSION](../VERSION) 保存一行完整应用版本。CMake、应用 About、DMG 文件名与发布脚本读取它；不在源代码或工作流中另写应用版本。

- Git 标签：`v` + `VERSION`，例如 `v0.1.0-alpha.1`。
- GitHub Release 标题：`M7Arc 0.1.0-alpha.1`。
- Apple Silicon 包：`M7Arc-0.1.0-alpha.1-macos-arm64.dmg`。
- Intel 包：`M7Arc-0.1.0-alpha.1-macos-x86_64.dmg`。
- Universal 2 包采用 `macos-universal2` 后缀，须同时包含完整 arm64 与 x86_64 依赖。
- `CFBundleShortVersionString` 保存数字部分 `0.1.0`；`CFBundleVersion` 使用同版本数字及 Apple 接受的开发后缀，例如 `0.1.0a1`。完整 SemVer 显示在 About 与发行文件名中。

引擎版本 `7-Zip 26.03`、Qt 版本与应用版本分别记录。升级引擎属于功能或修复变更，按实际用户影响选择应用 minor 或 patch，不把应用版本改成 7-Zip 的版本号。

## 阶段提交与公开版本

每个可审查阶段独立提交：构建与引擎、窗口与真实操作、格式和工具、macOS 集成、打包和发布。普通提交推送触发 CI；只有推送匹配 VERSION 的 `v*` 标签才发布 Release。预览标签创建 GitHub Pre-release，稳定标签创建正式 Release。

准备发布时，先把 CHANGELOG 中本次实际完成的内容移到对应版本，再更新 VERSION，提交并推送。标签始终指向这个已验证的提交；已公开标签保持不变。
